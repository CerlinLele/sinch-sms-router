# Working Rules

- Confirm the task scope before editing files.
- If the user asks for analysis, planning, or discussion, do not change code.
- If the request is to implement, make the smallest change that solves the task.
- Keep changes focused on the files and packages that belong to the request.
- Prefer clear, simple code over clever code.
- Run the relevant tests after code changes when possible.
- Do not revert unrelated user changes.
